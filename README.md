# 播浪

中文名：**播浪** · 前缀 `livewave` · 端口 **6400 / 11400**

## 骨架

**互动事件入流 → 事件时间水位线推进 → 热度窗关闭发射 → 迟到修正/撤回 → 窗输出与撤回互证**

皮：直播间点赞/送礼互动。去皮是事件时间窗计算 + 允许迟到与撤回，不是直播运营后台 CRUD，不是点击会话空闲切开。

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6400
# 入流 → 灌「准时热度样例」→ 水位线/热度窗 → 再灌「迟到修正样例」看撤回 → 贯验
```

## 主链对象

| 对象 | 作用 |
| --- | --- |
| 互动事件 | 带事件时/处理时的点赞送礼 |
| 水位线 | 每房事件时水位 + 允许迟到秒 |
| 热度窗 | 翻滚窗；开启累计，关闭发射 |
| 上限闸 | 单窗点赞合计触站规热度上限即整笔旁路（超额旁路口径），窗合计保持上限下最后合法值 |
| 超额摘要 | 上限处置的同票留证：窗键/上限/实际入窗额/截断额或旁路事件号/摘要号；撤回按其实收入窗额封顶回滚 |
| 撤回单 | 已关闭窗被允许迟到事件修正 |
| 旁路匣 | 超允许迟到 / 超热度上限 |
| 窗贯验 | 窗合计 ↔ 事件合计 ↔ 末次撤回 ↔ 上限闸 ↔ 超额摘要 |

## 上限闸（热度上限截断）

全局口径二选一，本系统选定**超额旁路**：触发上限的事件整笔不入窗、不改窗合计、
不落撤回单，进旁路匣留证（原因=超热度上限）；窗合计保持上限下最后合法值。
对侧口径「截断入窗」（窗合计=上限、事件部分入窗）不采用，两口径不混用。
判定与窗/撤回/旁路写入同事务，交错即整体回滚，失败闭不留半截。
只读接口 `GET /api/上限闸`、`GET /api/上限闸/窗?窗键=…`：上限、窗合计、旁路证据、valid。
夹具：`超上限旁路样例`（过大点赞→窗不变+旁路有）、`超额迟到并发样例`（顶格窗迟到修正越限→旁路无撤回，送礼修正→撤回不撕裂）。

## 超额摘要（甲·摘要入窗额封顶回滚）

全局设计取舍二选一，本系统选定**甲「摘要入窗额封顶回滚」**：

- 上限处置（触发事件整笔旁路）成功必须**同票**写超额摘要：窗键、上限、实际入窗额、
  截断额或旁路事件号、摘要号（`摘-` + 四元组规范 JSON 的 sha256）；摘要写失败整批回滚，
  禁止「处置成功摘要空」。
- 迟到撤回只动摘要入窗额：扣减不得超过被撤回事件摘要的实际入窗额，被旁路/截断的部分
  禁止当已入窗回滚（整笔旁路事件撤回扣 0，窗合计保持顶格）。
- 提交前核证三条硬约束：① 处置成功摘要空 → 整票回滚；② 扣减超摘要入窗额 → 整票回滚；
  ③ 摘要与窗合计分叉（合计跌破摘要入窗额 / 越上限）→ 整票回滚。
- 不采用乙「差额工单放行全额」：本库无差额工单概念，坚持按面额全额回滚一律驳回
  （HTTP 409，整票回滚）。
- 只读核证接口 `GET /api/核证/超额摘要[?窗键=…]`：逐行核证 + 口径常量 + 与上限写闸/旁路匣/
  撤回簿/热度页/对齐核验协同。夹具：`触顶后再撤回`（甲封顶扣减，合计不低于摘要入窗额）、
  `触顶全额回滚`（乙无差额工单→撤回失败闭）。

## 空桩（邻题扩展）

双钟水位线、允许迟到策略、撤回合并替换、房间级水位线、滑动窗切分、送礼加权热度、关窗并发半截、水位线回退禁改、旁路升格重放、多房串扰隔离、空窗发射策略、撤回幂等键、处理时乱序缓冲、窗键对齐互证、开播闭播切流。
